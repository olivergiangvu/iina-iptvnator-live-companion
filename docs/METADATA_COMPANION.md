# Python Metadata Companion — Install, Upgrade, Rollback

**Stable version:** v0.1.2 · macOS LaunchAgent · Python 3.10+ (stdlib only)

The Python service is the third component of [IPTVnator Live Companion](../README.md). It binds to `127.0.0.1:8766`, reads the existing IPTVnator SQLite database **read-only**, and makes Live/Catch-up EPG and channel artwork available to the IINA plugin. It does **not** play video. The original IPTVnator → IINA launcher v1.1 remains a completely separate executable.

## What is installed?

| Item | Source | Runtime location |
|---|---|---|
| Python service | `companion/server.py`, `logo.py`, `catchup.py` | Kept in a **permanent** source directory |
| LaunchAgent | Generated by `scripts/install-companion.sh` | `~/Library/LaunchAgents/io.github.olivergiangvu.iptvnator-live-companion.plist` |
| Health and status API | Python server | `http://127.0.0.1:8766/health` and `/status` |
| Logs | LaunchAgent stdout/stderr | `~/Library/Logs/iptvnator-live-companion.log` |

The LaunchAgent records the **absolute path** to the Python server. Moving or deleting that directory will stop the service from starting. Its `RunAtLoad` and `KeepAlive` settings start it on login and restart it after unexpected exits. There is no daemon running under root and no Docker service.

## Option A — Install from GitHub source checkout (current Mac deployment)

Run `./scripts/install-companion.sh` **once** after cloning the repo into a permanent location. If the LaunchAgent already exists, that script intentionally refuses to reinstall it.

For each **tested new release**, update the source then restart the existing LaunchAgent (do not reinstall):

```bash
cd "$HOME/Developer/iina-iptvnator-live-companion"
git switch main
git pull --ff-only
./scripts/upgrade-companion.sh
curl -fsS http://127.0.0.1:8766/health | python3 -m json.tool
```

The upgrade script refuses to restart a LaunchAgent pointing to a different source path. This protects machines with a separate or customized installation. The currently published v0.1.2 script checks that `/health` returns `version=0.1.2`.

For version-pinned deployments, use official GitHub release tags instead of blindly following `main`; retain a copy of the older checkout for rollback.

## Option B — Install from the official Release archive (new deployments)

The [v0.1.2 GitHub Release](https://github.com/olivergiangvu/iina-iptvnator-live-companion/releases/tag/v0.1.2) includes a standalone `IPTVnator-Metadata-Companion-0.1.2.tar.gz` archive. This package contains **only** the three Python modules, the three LaunchAgent lifecycle scripts, this guide and a SHA-256 manifest. No IPTVnator credentials, SQLite databases, logs, playback wrappers, IINA plugin binaries or user data are included.

Use a **permanent installation directory**, not a temporary Downloads folder:

```bash
ROOT="$HOME/Library/Application Support/IPTVnator Metadata Companion"
mkdir -p "$ROOT"
tar -xzf "$HOME/Downloads/IPTVnator-Metadata-Companion-0.1.2.tar.gz" \
  -C "$ROOT" --strip-components=1
cd "$ROOT"
./scripts/install-companion.sh
curl -fsS http://127.0.0.1:8766/health | python3 -m json.tool
```

Requirements: IPTVnator's database already exists at `~/.iptvnator/databases/iptvnator.db`; macOS LaunchAgents are available; `python3` is installed. The IINA `.iinaplgz` and the v1.1 launcher are separate Release assets.

### Upgrade an archive-based installation

Download the **next stable metadata archive** and extract it into the **same permanent directory**, then run its upgrade script. Before replacing source files, keep a copy of the old directory for rollback. Example for a future `vX.Y.Z`:

```bash
ROOT="$HOME/Library/Application Support/IPTVnator Metadata Companion"
cp -R "$ROOT" "$ROOT.backup"
tar -xzf "$HOME/Downloads/IPTVnator-Metadata-Companion-X.Y.Z.tar.gz" \
  -C "$ROOT" --strip-components=1
cd "$ROOT"
./scripts/upgrade-companion.sh
curl -fsS http://127.0.0.1:8766/health | python3 -m json.tool
```

If the version check fails, restore the backup source files in the **same** install path and restart the LaunchAgent. Avoid keeping the active server in a directory that gets renamed during updates; the plist path is fixed.

## Existing installations: do not migrate unnecessarily

If the Python service on your Mac already runs from the Git checkout in `~/Developer`, **keep that working deployment**. Do not install the Release tarball over a second path or run `install-companion.sh` again. The two distribution methods have the same server code but separate installation locations; only one local service should bind port 8766.

To inspect the active program path without exposing stream credentials:

```bash
python3 - <<'PY'
from pathlib import Path
import plistlib
p=Path.home() / 'Library/LaunchAgents/io.github.olivergiangvu.iptvnator-live-companion.plist'
with p.open('rb') as f:
    a=plistlib.load(f)['ProgramArguments']
print('Python:',a[0])
print('Server:',a[-1])
PY
```

## Version policy and automatic updates

- The **IINA plugin**, **Python Metadata Companion** and **launcher v1.1** are separate deployable pieces with separate installation locations.
- Stable updates are **manual and explicit**: retrieve a tested version and call the upgrade script. Merely publishing to GitHub does **not** change a running Mac.
- **No background updater or silent overwrite** is installed. Automatic Python module upgrades would risk interrupting streams and introducing EPG regressions.
- `install-companion.sh` registers LaunchAgent once; `upgrade-companion.sh` validates Python source, restarts it and checks health. `uninstall-companion.sh` removes only the LaunchAgent, leaving IPTVnator, the launcher and plugin untouched.
- The service does not write to IPTVnator's database. Keep secrets out of logs and issue reports.

## Uninstall

Run `./scripts/uninstall-companion.sh` from the actual installed source directory. This stops/removes only the LaunchAgent; it intentionally does not remove source files or the independent launcher/plugin.
